# 사이트 개선 기록 — 2026-11-09

기준: 운영 커밋 `6c6a5a0`, PC 1280px 및 모바일 375·320px의 홈·검색 결과·검색처 안내, Express/SSE 조회 흐름과 공개 도서관 HTML을 점검했습니다.

| 관찰한 문제 | 반영한 개선 | 검증 |
| --- | --- | --- |
| 화면에서 쓰는 SSE 검색은 JSON 검색 캐시를 사용하지 않아 같은 검색을 반복 요청 | 두 API가 도서관별 정상 결과 캐시와 진행 중 요청을 공유 | JSON→SSE 캐시 공유·만료·최대 크기·중복 요청 테스트 |
| 한 도서관의 오류에도 모든 검색처를 다시 조회해야 함 | 미완료 검색처 전체 또는 한 곳만 다시 확인. 기존 결과·필터 유지 | API 선택 조회와 모바일·PC 복구 시나리오 |
| ‘검색 중지’가 서버의 도서관 조회를 중단하지 않음 | 마지막 요청자가 연결을 끊으면 해당 외부 조회도 취소 | 실제 HTTP SSE 연결 종료 및 동시 요청자 취소 테스트 |
| 필터를 켜면 연결 실패가 ‘조건에 맞는 책 없음’으로 보일 수 있음 | 선택한 조건의 미완료 검색처를 계산해 미확인 상태·직접 검색 링크·재조회 표시 | 실패한 실물도서 검색처, 정상적인 전자책 0건을 분리 검증 |
| 공유·새로고침 시 필터와 정렬이 사라짐 | 주소에 필터·정렬 저장, 복원, 공유 복사 및 권한 거절 시 직접 복사 대체 화면 | 주소 왕복·실제 새로고침·클립보드 거절 테스트 |
| 같은 책·같은 이용 상태를 갱신하면 예약 수 등 부가 정보가 남을 수 있음 | 결과 카드 갱신 기준에 확인 시각·상태·예약 수 등 포함 | ‘새로 확인’ 후 예약 수 변경 표시 테스트 |
| 숨겨진 추가 소장처를 처음부터 모두 DOM으로 생성 | 펼칠 때 생성하고 펼친 상태 유지 | 펼치기 전 추가 행 0개, 펼친 뒤 실제 행 표시 |
| 첫 표지 주소가 실패하면 대체 표지가 있어도 빈 표지 표시 | 다른 검색처의 표지를 순서대로 시도 | 브라우저 화면 확인 |
| 일부 회색 안내문의 명암비 4.4:1, 모바일 보조 글자 9~10px | 안내문 색상 보강, 작은 글자·버튼 크기 개선, 진행률에 접근 가능한 이름·수치 추가 | axe WCAG A/AA 검사: 홈·결과·안내 각 375·320px에서 위반 0건 |
| Vercel 프록시 주소를 방문자 주소로 사용해 요청 제한이 섞일 가능성 | Vercel이 설정한 실제 방문자 IP를 사용하고, 로컬에서는 전달 헤더를 신뢰하지 않음 | IPv4·IPv6·로컬 헤더 무시 테스트 |
| 캐시·요청 제한용 메모리의 항목 수 제한이 불완전 | 정상 결과 캐시 256개 및 요청 제한 버킷 1000개로 제한 | 캐시 LRU 테스트와 코드 검토 |
| 회귀 검사가 특정 책의 오늘 대출·예약 상태에 의존 | 고정 HTML·제어 서버 검증으로 기존 회귀 명령 연결 | `npm test`, `npm run verify:regressions` |

Vercel 방문자 IP 처리 근거: [공식 요청 헤더 문서](https://vercel.com/docs/headers/request-headers).

## 검증의 한계

- 캐시는 실행 인스턴스 안에서만 공유됩니다. 다른 인스턴스나 재시작 이후에는 다시 조회합니다.
- 자동 접근성 검사는 모든 장애·보조기기 조합을 보장하지 않습니다. 키보드와 작은 화면은 별도로 확인했습니다.
- 외부 도서관의 점검·대출 상태 변화는 앱이 제어할 수 없습니다. 오류와 부분 수집을 감추지 않고 재조회 경로를 제공합니다.
